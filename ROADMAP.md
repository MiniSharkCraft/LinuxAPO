Playback internal-link recovery regression (2026-10-17; dirty local candidate
at HEAD `64efe9935734f5471d003da8669320d014cd9ed4`): a WirePlumber E2E first
removed one `skyapo.playback` DSP → `skyapo.playback.stream` link while both

creation on the PipeWire control loop with bounded exponential backoff and
handles asynchronous `pw_proxy` errors as well as `PW_LINK_STATE_ERROR`. The
E2E-only fault seam can refuse one `link-factory` creation or submit an invalid

`skyapo-pipewire-e2e-playback-wireplumber-link-error` test waits for a receipt

recover, the stale error clears, and callback allocation/deallocation counts
remain zero. The latest Release run passed **4/4**: realtime safety, ordinary
link-removal/refusal recovery, asynchronous proxy-error recovery, and output
switch/rollback (103.91 s total). Pinned clang-format 18.1.3, Python syntax,
and `git diff --check` passed. After rebuilding `skyapod` and the fault helper
under ASan/UBSan, focused CTest passed **3/3**: realtime safety, ordinary
link-removal/refusal recovery, and asynchronous proxy-error recovery. The
output-switch/rollback case and full sanitizer matrix were not run under
sanitizers in this increment; memory pressure and swap use increased during the
sequential E2Es, so further local heavy testing was deferred. These
private-graph tests do not prove uninterrupted samples while a link is absent,
physical sink unplug/replug, or ordinary desktop routing/hardware behavior.
